# 효도알림 — 부모님 복지 알리미

어르신이 받으실 수 있는 **새 복지**를 AI가 매일 찾아서, 어르신 본인이 아니라 **신청을 도와줄 사람**(자녀·가족, 가족이 없으면 생활지원사·요양보호사)에게 알려주는 앱입니다.

「2026 사회보장 데이터를 활용한 AI 혁신 아이디어 경진대회」 출품용 프로토타입입니다.

- PC·모바일 모두 지원하며, 앱처럼 설치할 수 있습니다(PWA).
- 어르신 정보는 **사용자 기기 안에만** 저장하고 서버로 보내지 않습니다.
- API 키는 브라우저에 두지 않습니다. GitHub Actions(Secrets)에서만 씁니다.

## 동작 구조

```
[매일 05:00, GitHub Actions]
 1) fetch.mjs   한국사회보장정보원 API → 중앙부처·지자체 복지사업 수집 (노년 대상, 바뀐 것만)
 2) extract.mjs Gemini 2번 모델(lite)    → 어르신 관련성 분류 + 보호자용 쉬운 한 줄 요약
                Gemini 1번 모델(primary) → 자격요건 문장 → 판정 규칙(JSON)
 3) build.mjs   docs/data/services.json 생성 → 저장소에 커밋

[사용자 기기, GitHub Pages]
 앱이 services.json을 내려받아 → 기기 안에서 어르신 정보와 규칙을 비교(판정 엔진)
 → 받을 가능성 높음 / 확인 필요 / 새 소식 → 알림
```

판정은 규칙 엔진(`docs/js/engine.js`)이 하고, AI는 규칙을 만들 때만 씁니다. 그래서 생성형 AI의 환각이 판정 결과에 섞이지 않습니다.

## AI API가 필요한가요?

**필요합니다.** 다만 **서버(GitHub Actions)에서 하루 한 번만** 씁니다. 앱을 쓰는 사람 수와 상관없이 호출 수가 일정합니다.

| 모델 | 기본값 | 하는 일 | 호출 방식 |
|---|---|---|---|
| 1번 | `gemini-3.8-flash` | 자격요건(나이·소득·수급 여부·거주기간 등) 구조화 | 사업 4건씩 묶어 1회 호출 |
| 2번 | `gemini-3.5-flash-lite` | 어르신 관련성 분류, 쉬운 한 줄 설명 | 사업 10건씩 묶어 1회 호출 |

Gemini 키가 없거나 한도를 다 쓴 날에는 간이 추출기(정규식)로 대신 채웁니다. 이때 앱은 '확인 필요' 위주로 안내하고, 다음 실행 때 AI로 다시 분석합니다.

### 무료 티어로만 쓰기

1. [Google AI Studio](https://aistudio.google.com/apikey)에서 **결제(Billing)를 연결하지 않은 프로젝트**로 API 키를 만듭니다.
   결제가 연결되지 않은 키는 무료 한도를 넘으면 요청이 거절(429)될 뿐, 요금이 청구되지 않습니다.
2. 코드에도 무료 한도 보호 장치가 있습니다(`scripts/lib/gemini.mjs`).
   - 분당 요청 수를 기본 4회(1번)·8회(2번)로 제한
   - 한 번 실행에 최대 60회(1번)·120회(2번)만 호출
   - 429 응답 시 한 번만 재시도하고, 일일 한도 초과면 그날은 중단
3. 실제 무료 한도는 모델마다 다르고 바뀔 수 있습니다. 한도가 더 낮으면 아래 Variables로 값을 낮추세요.

## 설치 방법

### 1. API 키 등록 (코드에 넣지 마세요)

저장소 **Settings → Secrets and variables → Actions → Secrets**에서 **New repository secret**을 누르고 아래 두 개를 등록합니다.

| 이름 | 값 |
|---|---|
| `DATA_GO_KR_KEY` | 공공데이터포털 일반 인증키 (Encoding·Decoding 어느 쪽이든 가능) |
| `GEMINI_API_KEY` | Google AI Studio API 키 |

> ⚠️ 키를 파일에 적어 커밋하면 공개 저장소에서 누구나 볼 수 있습니다. 반드시 Secrets에만 넣으세요.

공공데이터포털에서 아래 두 API의 활용신청이 되어 있어야 합니다.

- 한국사회보장정보원_중앙부처복지서비스
- 한국사회보장정보원_지자체복지서비스

### 2. (선택) 설정값 — Variables 탭

| 이름 | 기본값 | 설명 |
|---|---|---|
| `GEMINI_MODEL_PRIMARY` | gemini-3.8-flash | 1번 모델 |
| `GEMINI_MODEL_LITE` | gemini-3.5-flash-lite | 2번 모델 |
| `GEMINI_PRIMARY_RPM` / `GEMINI_LITE_RPM` | 4 / 8 | 분당 최대 호출 |
| `GEMINI_PRIMARY_MAX_CALLS` / `GEMINI_LITE_MAX_CALLS` | 60 / 120 | 실행당 최대 호출 |
| `LOCAL_DETAIL_CAP` / `CENTRAL_DETAIL_CAP` | 900 / 85 | 실행당 상세 조회 수 (개발계정 일일 트래픽 1,000 / 100 이내) |
| `LIFE_ARRAY` | 006 (노년) | `ALL`이면 전 연령 사업 수집 |

### 3. 앱 공개 (GitHub Pages)

**Settings → Pages → Build and deployment**에서 Source를 **Deploy from a branch**, Branch를 **main / `/docs`**로 지정합니다.
잠시 뒤 `https://<계정>.github.io/261103welfare/`에서 앱이 열립니다.

### 4. 데이터 갱신 실행

**Actions → 복지 데이터 갱신 → Run workflow**로 바로 실행할 수 있고, 이후에는 매일 자동으로 실행됩니다.
개발계정 트래픽 한도 때문에 노년 대상 사업 전체(약 1,500건)를 처음 모두 받는 데 2~3일이 걸립니다. 그 뒤로는 바뀐 사업만 받습니다.

## 로컬에서 실행

```bash
npm test                      # 판정 엔진 테스트
npm run serve                 # http://localhost:8080 미리보기
# 데이터 직접 갱신 (키는 환경변수로)
DATA_GO_KR_KEY=... GEMINI_API_KEY=... npm run update
```

회사·학교 네트워크처럼 보안 프로그램이 HTTPS를 검사하는 환경에서 `fetch failed (SELF_SIGNED_CERT_IN_CHAIN)`이 나오면, `NODE_OPTIONS=--use-system-ca`를 함께 지정하세요.

## 주요 기능

- **보호자 3유형**: 자녀·가족 / 생활지원사(노인맞춤돌봄) / 요양보호사(장기요양). 소속 기관은 직접 입력합니다.
- **어르신 등록**: 생년월일, 성별, 사는 곳(예: 서울특별시 종로구), 가구 형태·가구원 수, 기초연금·기초생활·차상위 여부, 장기요양등급, 대략적인 월 소득인정액. 장애·보훈 여부는 선택 항목이며 별도 동의가 필요합니다.
- **본인 동의**: 동의 요청 문자 보내기, 동의 방법과 시점 기록, 민감정보 별도 동의.
- **판정 결과**: 받을 가능성 높음 / 확인 필요 / 새 소식 / 처리함. 조건마다 ✓ ✕ ? 근거를 보여주고, 어떤 정보를 더 넣으면 정확해지는지 안내합니다.
- **신청 안내**: 지원 내용, 신청 방법, 문의처(누르면 전화), 서식, 복지로 링크.
- **기록**: 신청 완료 / 해당 없음 / 탈락 / (돌봄종사자) 방문 때 안내·안내함.
- **공유**: 가족에게 공유(카카오톡·문자), 가족 초대 링크로 형제자매가 같은 어르신을 등록.
- **알림**: 새 복지가 나오면 기기 알림. 안드로이드 크롬에 설치한 경우 하루 한 번 자동으로 확인합니다.
- **편의**: 글자 크기 3단계, 다크 모드, 오프라인 실행, 백업·복원.

## 알려진 한계와 다음 단계

- **앱이 닫혀 있을 때의 알림**: 정적 웹앱이라, 기기 알림은 앱을 열 때 또는 안드로이드 설치형의 주기적 확인으로만 동작합니다. 앱이 꺼져 있어도 자녀 휴대폰으로 즉시 보내려면 푸시 서버(FCM/Web Push)나 카카오 알림톡(비즈니스 채널·건당 비용)이 필요합니다. 2단계 과제입니다.
- **판정은 안내용**입니다. 소득인정액에는 재산 환산액이 포함되므로 실제 자격은 신청 기관의 심사로 결정됩니다.
- AI 정확도 검증용으로 행정안전부 「대한민국 공공서비스(혜택) 정보」 API 연계를 계획하고 있습니다.
